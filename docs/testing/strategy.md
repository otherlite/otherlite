# 测试策略

## 思考维度（每次都问）

- **边界**：空输入、最大输入、off-by-one、负数、unicode、超长字符串、特殊字符（引号、反斜杠、emoji、null byte）
- **状态**：未登录、session 过期、权限不足、数据陈旧、并发修改后的旧版本
- **并发**：两个请求竞争、用户双击、任务重试、分布式锁失效
- **失败**：DB 宕机、API 超时、磁盘满、第三方返回 500、网络抖动
- **数据**：早于本次改动的存量行、半迁移状态、null/缺失字段、跨时区
- **回归**：周边哪些功能可能被打坏 —— 查调用点和共享依赖

## 测试质量底线

- **能集成测就不 mock。** Mock 隐藏接缝处的 bug。
- **测试必须真的运行被测行为**，不能只是调用函数断言不抛。
- **一个测试一个概念。**
- **不写 flaky 测试。** 时序相关用 fake/正规等待，不用 `sleep`。
- **Skip ≠ Pass。** 跳过要明显标 TODO + 原因。
