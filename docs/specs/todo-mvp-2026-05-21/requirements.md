# Todo MVP Web —— 需求文档

## 1. 目标（Goal）

提供一个最小可用的 Web Todo 应用，让单一用户在浏览器内完成"记一件事 → 看到它 → 标记完成 → 清理"的闭环。

## 2. 背景 / 动机

- 用户想要一个"最小 MVP"版本的 todo web，用来验证产品最核心的价值：**写下要做的事 + 跟踪完成进度**。
- MVP 的目的：用最少的功能跑通主流程，避免被认证、协作、多端同步这些"将来再说"的话题拖住。
- 选 Web 而非 CLI/桌面：浏览器零安装、跨设备查看（即便不同步）、最贴近"todo 工具"用户预期。
- 立项时间：2026-05-21。

## 3. In Scope

- 单用户、本地使用的 Web 应用（一个浏览器窗口 = 一个使用者）。
- Todo 的核心 CRUD：创建、查看列表、编辑文本、删除。
- 完成状态切换：未完成 ⇄ 已完成。
- 列表视图：能区分未完成与已完成（顺序或分组都算满足）。
- 数据持久化：刷新页面后数据仍在（localStorage 或后端任一即可，由 architect 定）。
- 空状态提示：列表为空时给一句友好引导文案。

## 4. Out of Scope

以下明确**不在** MVP 范围，遇到时直接拒绝：

- 用户账户 / 登录 / 注册 / 鉴权。
- 多端同步、多设备共享、跨浏览器同步。
- 协作分享（@他人、分配、评论）。
- 截止日期、提醒、通知、日历集成。
- 标签 / 分类 / 项目 / 文件夹 / 优先级排序。
- 富文本、附件、子任务、嵌套。
- 拖拽排序、批量操作、撤销 / 重做。
- 搜索、筛选（仅"全部 / 未完成 / 已完成"切换属 P2，不强求）。
- 国际化（i18n）、多主题切换。
- 后端 API 对外开放、第三方集成、Webhook。
- PWA / 离线安装、移动端原生体验优化。
- 数据导入 / 导出 / 备份。
- 操作审计、埋点分析。

## 5. 用户故事

> 单一角色：**User**（匿名使用者，无登录概念）。

### P0 —— 没它产品不可用

- **US-1 创建 Todo**：作为 User，我想输入一条文字并提交，把它加入我的待办清单。
- **US-2 查看列表**：作为 User，我想打开页面就能看到我所有的待办事项。
- **US-3 切换完成状态**：作为 User，我想点击某条待办把它标记为已完成（或反向取消完成）。
- **US-4 删除 Todo**：作为 User，我想删除一条不再需要的待办。
- **US-5 数据持久化**：作为 User，我刷新页面或重开浏览器后，仍能看到之前的待办。

### P1 —— 强烈应有

- **US-6 编辑文本**：作为 User，我想修改某条待办的文字描述（输错或想改）。
- **US-7 区分完成/未完成的视觉态**：作为 User，我想一眼看出哪些已完成、哪些还没做。
- **US-8 空状态引导**：作为 User，列表为空时给我一句话提示我去添加第一条。

### P2 —— 锦上添花

- **US-9 视图筛选**：作为 User，我想在"全部 / 未完成 / 已完成"之间切换，只看我关心的子集。
- **US-10 一键清除已完成**：作为 User，我想用一个按钮清掉所有已完成项。
- **US-11 剩余计数**：作为 User，我想看到"还有 N 条未完成"。

## 6. 验收标准

每个 P0/P1 故事至少一条 Given/When/Then。P2 在实现时再补。

### US-1 创建 Todo
- **Given** 我在 Todo 主页，输入框为空 **When** 我输入非空文本并按回车（或点击"添加"按钮）**Then** 列表顶部（或底部，由设计定）出现该条目，输入框被清空。
- **Given** 输入框为空或仅空白字符 **When** 我提交 **Then** 不创建任何条目，不报错（静默忽略或浅提示）。
- **Given** 我输入超过合理长度（建议上限 200 字符）**When** 我提交 **Then** 要么截断要么阻止提交并提示，**禁止**无限制保存。

### US-2 查看列表
- **Given** 我已有 ≥ 1 条 todo **When** 我打开页面 **Then** 所有 todo 按稳定顺序（创建时间倒序或正序，由设计定）渲染。
- **Given** 列表内有任意条目 **When** 渲染完成 **Then** 每条至少显示：文本、完成状态、删除入口。

### US-3 切换完成状态
- **Given** 一条未完成 todo **When** 我点击其完成控件（checkbox 或按钮）**Then** 它立刻变为已完成态（视觉反馈 + 数据更新）。
- **Given** 一条已完成 todo **When** 我再次点击完成控件 **Then** 它恢复为未完成态。

### US-4 删除 Todo
- **Given** 一条 todo **When** 我点击其删除入口 **Then** 它立即从列表移除并从持久化中消失。
- **Given** 我刚删除一条 todo **When** 我刷新页面 **Then** 它不会再出现（删除是持久的）。

### US-5 数据持久化
- **Given** 我创建 / 修改 / 删除了若干 todo **When** 我刷新页面 **Then** 列表与刷新前完全一致。
- **Given** 我关闭并重开浏览器标签页（同一浏览器、同一域）**Then** 数据仍然保留。

### US-6 编辑文本
- **Given** 一条 todo **When** 我触发编辑（双击或点击编辑入口）**Then** 文本进入可编辑态，能修改并保存。
- **Given** 我编辑后保存为空 **Then** 视为删除该 todo 或拒绝保存（二选一，由设计定，不可保存空文本）。

### US-7 区分完成/未完成的视觉态
- **Given** 一条已完成 todo **When** 渲染 **Then** 在样式上明显区别于未完成项（例如：删除线、颜色变灰、checkbox 勾选）。

### US-8 空状态引导
- **Given** 列表中没有任何 todo **When** 我打开页面 **Then** 显示一句引导文案（例：「还没有待办，加一条试试」）。

## 7. 非功能性约束

MVP 阶段宽松，但有底线：

- **性能**：100 条 todo 内交互延迟 < 100 ms；首屏渲染 < 2 s（本地或回环网络）。
- **可用性**：核心流程（创建/勾选/删除）≤ 1 次点击或键盘操作完成。
- **安全**：纯本地数据，无敏感字段；但渲染用户输入时必须做 XSS 转义，不可 `innerHTML` 拼接。
- **可访问性**：表单控件有 `label`，可用键盘（Tab + Enter + Space）完成全部 P0 操作。无需达到 WCAG AA 全套。
- **浏览器兼容**：最新两个主版本的 Chrome / Safari / Firefox / Edge。不支持 IE。
- **国际化**：仅中文或仅英文一种文案即可（由设计定），不做 i18n 切换。
- **隐私 / 合规**：数据不出本机（localStorage 方案）或仅落本项目自有后端（如选后端方案）；不接第三方分析 SDK。

## 8. 数据与状态

### 实体：Todo

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string | 稳定唯一标识（UUID 或自增字符串，由 architect 定） |
| `text` | string | 用户输入的待办文本，1–200 字符 |
| `completed` | boolean | 是否已完成 |
| `created_at` | ISO 8601 | 创建时间（用于排序） |
| `updated_at` | ISO 8601 | 最近一次修改时间（可选，便于排查） |

### 生命周期

`new → active(未完成) ⇄ completed(已完成) → deleted（物理删除，不保留 tombstone）`

### 读写权限

单用户、无鉴权，所有数据对当前浏览器会话完全开放。**不**做软删除、不做版本历史。

## 9. 依赖与集成

- **运行时**：Node 20+，pnpm 10，turbo 2（项目铁律）。
- **前端框架**：由 architect 选型（React / Vue / Svelte / 纯 HTML 任一，需评估 MVP 体量）。
- **持久化**：默认 localStorage（最简）。若 architect 判断需要后端，可引入轻量后端（如 SQLite + 单进程 Node），但需在设计文档中论证收益。
- **外部服务**：无（无第三方 API、无 CDN 强依赖）。
- **部署**：本地 `pnpm dev` 跑起来即算 MVP 达标，不强求生产部署。

## 10. Open Questions

> autopilot 模式下做出的合理假设，列在此处供 architect 复核；不阻塞设计。

1. **持久化方案**：默认 localStorage（最贴近"最小 MVP"），如 architect 认为后端更合适请在 design 中说明。
2. **前端框架选型**：留给 architect。MVP 体量小，React + Vite 是常见默选，Svelte / 纯 HTML 也可。
3. **样式方案**：默认原生 CSS 或一个轻量 utility 方案（如 Tailwind）即可，不强求设计系统。
4. **排序规则**：创建时间倒序（新的在上）作为默认假设；如有更好的产品直觉，architect 可调整并说明。
5. **编辑触发方式**：双击进入编辑 vs 显式编辑按钮——默认双击（节省界面），但显式按钮可访问性更好；由 architect / 设计定。
6. **空文本编辑保存的处理**：默认"拒绝保存并恢复原文"；如选"视为删除"也合理。
7. **筛选/清除已完成/计数（US-9/10/11）**：P2，若实现成本极低（< 半天）建议带上，否则推迟。

以上假设均不阻塞 architect 开工——任意一种合理选择都能让 P0/P1 跑通。
